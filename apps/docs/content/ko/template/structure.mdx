# 코드 구조와 린트

`app`과 `admin`은 사용자 유형별 서비스입니다. 각 서비스 안에서 API와 상태를 도메인별로 나누고, 화면은 라우트별로 둡니다.

```text
src/
  app/                        # Next.js routes and layouts
  services/
    app/                      # End-user service
      page/{route}/           # UI
      state/{domain}/         # Models, queries and actions
      api/{domain}/           # Server functions
    admin/                    # Admin service, same layers
  server/repository/          # Data access
  lib/                        # Shared code and UI components
.agents/skills/               # Setup skills
.storybook/                   # Page stories and API mocks
eslint-rules/                 # Custom lint rules
AGENTS.md                     # Project instructions
```

<a id="layers"></a>

## 계층별 역할

| 경로                | 역할             |
| ------------------- | ---------------- |
| `src/app`           | URL과 레이아웃   |
| `page/{route}`      | 화면 구현        |
| `state/{domain}`    | 상태·쿼리·액션   |
| `api/{domain}`      | 서버 처리와 검증 |
| `server/repository` | 데이터 조회·저장 |
| `lib`               | 공통 UI와 도구   |

의존성 방향: `page → state → api → repository`.

<a id="what-enforces-it"></a>

## 린트가 검사하는 규칙

`eslint-rules/`에 정의한 커스텀 규칙을 `.oxlintrc.json`에서 활성화하고 **Oxlint**로 실행합니다. 다음은 주요 검사 항목입니다.

| 규칙                                    | 검사 내용                                                                       |
| --------------------------------------- | ------------------------------------------------------------------------------- |
| `api-structure`, `state-structure`      | 도메인 `index.ts`를 기준으로 필수 파일·액션 폴더·export 확인                    |
| `app-structure`                         | `src/app/page.tsx` 금지. 홈은 `(app)/page.tsx`에 배치                           |
| `index-only-import`                     | 다른 계층에서 API·상태의 actions/types 등 내부 경로 직접 import 제한            |
| `client-component-no-api-import`        | 서비스의 클라이언트 페이지에서 API 직접 import 금지                             |
| `api-only-server-action`                | 클라이언트 페이지의 직접 `fetch`와 허용 경로 외 API 라우트 제한                 |
| `no-db-in-api`                          | API 계층의 `drizzle-orm` 직접 import 금지                                       |
| `api-create-action`, `api-action-error` | API 액션 래퍼와 오류 처리 방식 검사                                             |
| `no-native-interactive`                 | 서비스 UI의 기본 HTML 버튼·입력 대신 설치된 컴포넌트 사용. `_components`는 제외 |

`pnpm run validate`가 타입 검사와 린트를 실행합니다. 그 외 작성 순서, 서비스 분리, 디자인 기준 등은 `AGENTS.md`와 `.ai.md` 가이드에 정의되어 있습니다.
