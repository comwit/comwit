# Dedicated skills

`shop-setup` handles the first storefront request: choose a direction from the [real examples](/template/docs/shop/overview), adapt the existing pages and add Storybook states using mock APIs. Shared instructions remain in [Agent guides](/template/docs/agents).

<a id="resources"></a>

## Database and storage through MCP

The skill inspects project context and available Comwit tools first. It reuses existing bindings, and uses `setup_database` / `setup_storage` only when the connection is needed and authorized. `list_cloud_resources` checks readiness; `get_local_env` and the returned `nextSteps` recover local configuration. It does not invent IDs or replace the commerce schema. A mock-only project keeps the user's explicit deferred resource choice.

<a id="complete"></a>

## Finish once, keep developing

After the requested pages, Storybook states and visual checks are complete, the helper runs validation, commerce tests, agent tests and a Storybook build. Only after all succeed does it remove the one-time skill, its Claude pointer and unused reference files inside that skill. Failed or pending work keeps the skill for resuming.

Pages, stories, public assets, service connections and ongoing skills (`refactoring`, `seo-optimize`, `video-offload`) stay in place. An asset still referenced by the app blocks cleanup until moved to a persistent path. The template source repository always retains its distributable skill. Progress is stored locally in `.agents/state/shop-setup.json`.
